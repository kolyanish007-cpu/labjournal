# Спецификация: Поиск и теги

Статус: утверждена. Реализация: milestone 1.

## Полнотекстовый поиск (FTS5)

```sql
CREATE VIRTUAL TABLE entries_fts USING fts5(
    title, body_md, tags,
    content='entries', content_rowid='rowid', tokenize='unicode61'
);
```

- Так как `entries` не имеет rowid-синхронизации через обычные триггеры
  (append-only), индекс пополняется в той же транзакции, что и INSERT записи:
  `INSERT INTO entries_fts(rowid, title, body_md, tags) VALUES (...)`,
  где `tags` — строка тегов через пробел. `rowid` = `seq` записи.
- Синтаксис запроса — FTS5 MATCH (`AND` по умолчанию, поддержка `"фраза"`,
  `OR`, `*`). Ошибочный синтаксис перехватывается и превращается в понятное
  сообщение UI, а не в исключение.
- Результат: список записей, отсортированный по релевантности (`bm25`),
  с подсветкой совпадений (в UI — жирным, без изменения БД).

## Теги

- Автодополнение при вводе: список существующих тегов, отфильтрованный по
  подстроке (`QCompleter`).
- Фильтр по тегам в боковой панели: мультивыбор, логика AND; счётчик записей
  у каждого тега.
- Переименование тега — разрешено (это не запись журнала, а служебная
  сущность); удаление тега открепляет его от записей, не трогая записи.

## Критерии приёмки

- Поиск находит по слову из заголовка, из тела и по тегу (тесты).
- Поиск с некорректным FTS-синтаксисом возвращает пустой результат с
  предупреждением, а не падает (тест).
- Фильтры (теги + даты) комбинируются с текстовым запросом (тест).
- Поиск по 10 000 записей выполняется < 100 мс (тест с генерацией данных).
