# Спецификация: Вложения

Статус: утверждена. Реализация: milestone 1.

## Поведение

1. Пользователь прикрепляет файл(ы) к записи (drag-and-drop или кнопка).
2. Ядро копирует файл в `<app_data_dir>/attachments/<uuid>__<safe_filename>`,
   где `safe_filename` — оригинальное имя, очищенное от символов
   `\ / : * ? " < > |` и обрезанное до 120 символов.
3. В `attachments` пишется запись: оригинальное имя, относительный путь,
   SHA-256, размер, mime (по расширению через `mimetypes`; по умолчанию
   `application/octet-stream`).
4. Оригинал файла пользователю больше не нужен — журнал хранит собственную
   копию. Удаление вложения из записи (в новой correction-записи) помечает
   строку флагом `removed_at` (добавить колонку в миграции 001 сразу), файл
   с диска не удаляется.

## Превью в UI

- Изображения (`image/*`): миниатюра до 200 px по большей стороне, клик —
  просмотр в диалоге с масштабированием.
- Остальные типы: строка с иконкой типа, именем, размером и SHA-256
  (первые 12 символов), кнопки «Открыть» (`QDesktopServices.openUrl`) и
  «Показать в папке».

## Критерии приёмки

- Повторное добавление того же файла к той же записи создаёт одну копию
  (дедупликация по `sha256` в пределах записи — тест).
- `verify_attachments` обнаруживает отсутствующий и подменённый файл (тесты).
- Имена файлов с не-ASCII (кириллица) сохраняются корректно (тест).
- Ограничение размера одного файла — 500 МБ, с понятной ошибкой UI (тест).
