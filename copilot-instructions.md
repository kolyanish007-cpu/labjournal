# Инструкции для кодинг-агентов (GitHub Copilot и др.)

## Что это за проект

`labjournal` — однопользовательский электронный лабораторный журнал (ELN).
Десктоп-приложение на Python + PySide6, данные в локальной SQLite-базе.
Целевая ОС пользователя — Windows, но код должен оставаться кроссплатформенным
(POSIX-пути, `pathlib`, без win32-вызовов).

## Архитектурные правила (нарушать нельзя)

1. **Слои.** Код делится на `core/` (доменная логика, БД, файлы — без Qt) и
   `ui/` (PySide6). Ядро не импортирует ничего из `ui`. UI не выполняет SQL
   напрямую — только через API ядра.
2. **Append-only записи.** Записи экспериментов никогда не UPDATE-ятся и не
   DELETE-ятся. Исправление — новая запись с полем `supersedes_id`, указывающим
   на предыдущую. Единственное исключение — служебные таблицы поисковых
   индексов (FTS), которые пересобираются триггерами.
3. **Идентификаторы.** Первичные ключи — UUIDv4 (TEXT), не автоинкремент.
   Порядок записей определяется монотонным счётчиком `seq` и меткой времени.
4. **Хеш-цепочка.** Каждая запись содержит `prev_hash` и собственный `hash`
   (SHA-256 канонического представления). Изменение истории должно быть
   обнаружимо функцией `core.integrity.verify_chain()`.
5. **Вложения.** Файлы копируются в хранилище приложения (никаких ссылок на
   пользовательские пути). SHA-256 содержимого — часть записи в БД.
6. **Снимки протоколов.** Эксперимент хранит копию текста/версии протокола на
   момент создания. Изменение шаблона протокола не влияет на старые
   эксперименты.
7. **Миграции схемы.** Любое изменение схемы — только через новый
   нумерованный миграционный скрипт в `core/db/migrations/`. Нельзя править
   уже применённые миграции.

## Стиль кода

- Python 3.11+, полные type hints (`list[str]`, не `List[str]`).
- Docstrings в стиле Google для публичных функций ядра.
- Форматирование и линт: `ruff` (конфиг в `pyproject.toml`). CI падает на
  ошибках линтера.
- Тесты: `pytest`, минимум один тест на каждую публичную функцию ядра.
  Тесты ядра не должны требовать Qt (использовать tmp_path-фикстуру для БД).
- Именование: `snake_case`, классы `PascalCase`, константы `UPPER_CASE`.
- Комментарии и docstrings — на английском; пользовательские строки
  интерфейса — на русском (готовность к i18n: строки UI собирать в одном
  модуле `ui/strings.py`).

## Запрещено

- Сетевые вызовы в `core/` (ядро обязано работать офлайн).
- Прямые SQL-запросы вне `core/db/`.
- Хранение путей пользователя в БД как единственной ссылки на вложение.
- Ломающие изменения схемы без миграции и теста на миграцию.
- Добавление зависимостей без обсуждения в issue (минимизировать дерево
  зависимостей).

## Определение готовности (Definition of Done)

- `ruff check .` и `pytest` проходят локально и в CI.
- Новая функциональность покрыта тестами, включая негативные сценарии
  (повреждение БД, отсутствие файла вложения, нарушение хеш-цепочки).
- Спецификация из `docs/specs/`, которой соответствует задача, выполнена
  буквально; отступления фиксируются в описании PR.
